# 자동 제어와 전원 연결 설계

## 제어기 구성과 기존 코드의 관계

R3 Nano는 HX711, 인증, 도어 잠금 및 Timer1 코일 제한을 이미 사용한다. 여기에 Servo 라이브러리를 붙여 Timer1을 공유하지 않는다. **별도 모션 MCU**가 M1/M2/M3와 추가 센서를 담당하고, R3 잠금 제어기와 확인 신호를 교환하는 구조다. 이 폴더는 제어 코어와 통합 명세를 제공하며, 테미 앱·R3 펌웨어의 기존 프로토콜을 수정하지 않았다.

`controller_reference.hpp`는 실제 측정된 위치·스위치 상태를 넣으면 다음 목표와 코일 요청을 반환한다. `tests/controller_test.cpp`는 전체 순서와 고장 정지를 호스트에서 확인한다. 다음 하드웨어 어댑터는 실제 MCU 선정 후 구현해야 한다: XM430 half-duplex TTL, 2축 STEP/DIR, 4개 선형 센서 ADC, 스위치 입력, 모터 프로파일, 인증된 요청 전달, watchdog.

실제 설치에서는 기존 Nano의 잠금 인증·코일 제한을 우회해 모션 MCU가 코일 MOSFET을 직접 켜지 않는다. Nano 측에 승인된 자동 사이클/후퇴 요청과 응답을 연결하고, 잠금핀 실제 상태를 모션 MCU에 전달한다. 테스트 입력의 `openRequest/closeRequest`는 인증을 마친 이벤트이며 임의 문자열 명령이 아니다.

## 모션 MCU I/O 할당표

MCU는 ADC 4채널 이상, 하드웨어 UART와 충분한 GPIO가 있는 보드로 선정한다. 아래는 **커넥터의 신호 이름**이며 특정 보드 핀 번호를 이미 검증했다는 뜻이 아니다.

| 커넥터 | 연결 | 조건 |
|---|---|---|
| J_M1 | +12V_M1, GND, DXL_DATA | XM430-W350-**T**의 TTL half-duplex. RS485형 -R과 혼용 금지. 실제 MCU 전압에 맞는 트랜시버 |
| J_M2 | STEP_LOW, DIR_LOW, EN_LOW, GND → 전류 제한 드라이버 | 모터 4선은 드라이버 A+/A-/B+/B-. 0.4A/상 이하로 시작 |
| J_M3 | STEP_HIGH, DIR_HIGH, EN_HIGH, GND → 전류 제한 드라이버 | M2와 같은 구성. 앞뒤 나사는 기계 벨트로 동기화 |
| J_HOME | LOW_FRONT_HOME, LOW_REAR_HOME, HIGH_FRONT_HOME, HIGH_REAR_HOME, GND | 각 나사에 별도 하한 스위치. 단선 시 홈으로 인정하지 않는 접점 구성 |
| J_UPPER | LOW_FRONT_UPPER, LOW_REAR_UPPER, HIGH_FRONT_UPPER, HIGH_REAR_UPPER, GND | 상한 스위치를 드라이버의 하드웨어 방향 차단에도 연결 |
| J_POS | LOW_FRONT_POS, LOW_REAR_POS, HIGH_FRONT_POS, HIGH_REAR_POS, VREF, GND | 독립 100mm 선형 위치센서 4개. 스텝 카운터만으로 위치 판단 금지 |
| J_LID | HINGE_ANGLE, LID_OPEN, LID_CLOSED, GND | M1 내장 엔코더와 별개로 실제 힌지각 확인. 벨트 파손/미끄러짐 검출 |
| J_SEAT | TRAY_SEAT_A/B/C, GND | 계량 프레임 위 판의 3지점 비접촉 안착 확인. 기계 스위치 힘이 판에 추가 하중을 주지 않도록 설계 |
| J_STOP | ESTOP_NC, EDGE/OBSTRUCTION, GND | 비상정지와 끼임/접근 감지. E-stop은 펌웨어와 별개로 모터 에너지 차단 |
| J_LOCK | 인증된 cycle 요청/응답, PIN_RETRACTED, PIN_EXTENDED, GND | Nano 보안/코일 타이머 유지. 서로 다른 논리전압이면 레벨 변환 |
| J_ROBOT | 정지 상태·상태 유효기간·인증된 열기/닫기 요청 | 테미 앱/상위 제어기가 갱신. 통신 단절 시 진행하지 않음 |

실물 핀 배치·브레이크·손 감지 부품을 확정하기 전에는 이 표를 완성 배선도나 즉시 업로드용 펌웨어로 취급하지 않는다.

## 전원 예산

기존 R3의 T1A 단일 입력과 5V 센서 전원을 모터 공통 전원으로 사용하지 않는다. 아래 전류는 **12V 안정화 5A 벤치 전원** 선정을 위한 예산이며 테미의 액세서리 포트에서 이 전류를 꺼낼 수 있다는 뜻이 아니다.

| 분기 | 계획 |
|---|---|
| M1 | 12V 직접 공급, 독립 분기 보호. 제조사 2.3A stall 전류를 설계 상한 검토에 포함. MCU/USB 5V에서 전원 공급 금지 |
| M2·M3 | 각각 전류 제한 드라이버. 0.4A/상, 상저항 30Ω 기준 두 상의 구리 손실 약 9.6W/모터; 드라이버 손실 포함 약 1A/분기 예산 |
| L1 코일 | 기존 12V 보호 분기·플라이백 다이오드·MOSFET·독립 2초 차단 유지. 잠금 코일 동작과 승강을 겹치지 않게 순서 제어 |
| 제어·센서 | 별도 12→5V DC/DC. HX711 아날로그 전원·접지를 모터 전류 경로와 분리 |
| 입력 | 12V/5A 기준 전력 60W. 도체·커넥터 허용전류·모터 과도전류 측정 후 퓨즈 정격 확정. 기존 T1A에 모터를 추가 직결하지 않음 |

M1과 M2/M3는 동시에 이동시키지 않는다. 뚜껑을 연 채 승강 중에도 M1 유지 전류는 존재하므로 전원 측정에 포함한다. 모터 배선은 꼬고 HX711 신호선과 떨어뜨린다. 스타 접지를 사용한다. USB와 외부 5V 중복 급전은 막는다.

## 실제 제어에서 지켜야 할 조건

- 부팅 시 현재 각도를 모르면 움직이지 않는다. 닫힘·잠금·받침 안착·네 홈과 위치가 모두 확인될 때만 Closed로 진입한다. 열린 상태의 재부팅은 사람이 상태를 확인한 서비스 복구 절차로 처리한다.
- 뚜껑 105°를 실제 힌지센서와 열림 스위치로 확인해야 받침을 올린다.
- 수평 승강은 양쪽이 공통 진행률을 따라 움직인다. 현재 높이와 목표 높이를 각각 선형 보간하고, 독립 속도 명령으로 두 축을 따로 끝까지 보내지 않는다.
- 앞뒤 위치 차이 0.8mm 초과, 센서 값 NaN/범위 오류, 동시에 들어온 상반 스위치, 200ms 초과 위치 정보, 오래된 테미 정지 상태는 고장이다.
- **경사 해제 → 받침 하강 → 안착 → 축 주차 확인**이 끝나기 전 뚜껑을 닫지 않는다.
- 뚜껑 6° 위치에서 멈춘 뒤 잠금핀을 후퇴시켜 마지막 구간만 닫는다. 10초간 코일을 계속 켜고 닫는 방식을 사용하지 않는다.
- 코일 후퇴 확인 500ms, 최대 연속 통전 2초, 기존 R3의 최소 6초 휴지와 watchdog/Timer1 차단을 유지한다. 모션 MCU 출력은 요청일 뿐이며 Nano가 다시 제한한다.
- 끼임, 과전류, 통신 단절, 스위치 모순 발생 시 목표를 현재 측정 위치로 동결하고 고장을 유지한다. 물건이 없어졌다는 이유로 닫거나, 통신 복구만으로 재시작하지 않는다.
- `weightValid`는 닫힘·축 주차·판 안착·정지·로드셀 안정화가 모두 확인된 후에만 참이다. 모터 종료 후 R3의 안정화 창을 다시 채운다.
- `readyToTravel`이 유효하고 새로 인증된 상태여야 테미 이동을 허용한다. 이 C++ 코어만으로 테미 주행을 정지시키는 기능은 없다.

자동화의 작동 순서는 구현·검사했지만 현재 폴더에는 실제 배선된 하드웨어, 앱의 새 프로토콜 어댑터, 교정한 센서와 완성 PCB가 없다. 실제 구동 완성 판정은 해당 부품을 연결한 전체 왕복시험 후 내린다.
